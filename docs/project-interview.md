# 项目面试实战

本模块只整理能够由真实经历支撑的项目回答。每道题都区分：

- **已实现：** 项目中真实做过，可以直接使用“我负责”“我们采用”。
- **演进方案：** 当前没有完成，只能使用“如果继续建设，我会……”。
- **表达边界：** 没有压测记录、线上指标或真实事故时，不补造数字。

## 项目入口

| 项目 | 项目状态 | 面试重点 | 详细问答 |
| --- | --- | --- | --- |
| Chat-BFI | 公司内部开发，因部门调整和业务线取消而未上线 | LangGraph、Text2SQL、状态、人工确认、SQL 语义校验 | [Chat-BFI 项目问答](/projects/chat-bfi-interview) |
| BFI | 已在成都、黑龙江落地 | Kafka/Flink/Doris/ES、海量数据、查询设计、单体架构 | [BFI 项目问答](/projects/bfi-interview) |

## 回答约束

### Chat-BFI

- 团队由一名前端和一名后端组成，后端由你负责。
- LangGraph 流程由代码固定，模型只负责明确的语义节点。
- 人工确认发生在任务计划生成后。
- SQL 当前只完成语法校验和趋势/明细特征检查。
- 没有实现 AST 白名单、`EXPLAIN`、只读账号、统一超时等完整防线时，不得说成现状。
- 项目不是 ReAct Agent。固定节点调用固定 Tool 不属于 ReAct。
- Doris View 是逻辑视图，不保存物化结果。

### BFI

- 项目每日处理约 20 亿条原始记录，每条原始记录包含 8 个字段，原始数据保留半年。
- “TB 级”表示累计数据规模；没有存储占用记录时不回答具体 TB 数。
- 全量数据按周拆表、表内按天分区；布控数据按月拆表。
- 这属于 Doris 大表组织与查询路由，不包装成传统 MySQL 分库分表。
- Flink Checkpoint 负责状态和消费位置恢复，端到端不重仍取决于 Sink 的事务或幂等能力。
- 反压和 OOM 要定位算子、数据倾斜和状态增长，不能只回答“增加 JVM 内存”。

## 通用答题结构

每个项目问题优先使用以下顺序：

1. 先给结论。
2. 说明真实业务背景和数据规模。
3. 解释自己负责的边界。
4. 展开技术流程及选择原因。
5. 说明风险、限制和取舍。
6. 没有量化证据时，明确说“未做压测，不能给出优化比例”。

## 30 秒项目选择

面试官关注 AI Agent、Python 或大模型工程时，主讲 Chat-BFI；关注 Java 后端、实时计算、大数据查询或系统架构时，主讲 BFI。

Chat-BFI 用来证明你能把模型放进受控工作流；BFI 用来证明你处理过真实上线系统和大规模数据链路。两个项目不要混用上线状态、数据规模和故障案例。
