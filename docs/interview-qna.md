# 高频追问与回答模板

## Java

### HashMap 底层结构是什么？

答题要点：数组 + 链表 + 红黑树；hash 扰动；扩容；线程不安全；为什么 key 要重写 equals/hashCode。

项目连接：标签字典、临时聚合、去重集合都可能用 Map，面试时要说清楚并发场景不能直接用 HashMap。

### 线程池参数怎么设置？

答题要点：看任务类型。CPU 密集型接近 CPU 核数；IO 密集型可适当放大；队列不能无限大；拒绝策略要结合业务。

项目连接：日志异步落库、大模型批量打标、报表任务都可以用独立线程池隔离，避免互相拖垮。

## Spring

### Spring 事务什么时候失效？

答题要点：同类内部方法调用、方法不是 public、异常被吞掉、没有被 Spring 管理、多数据源配置不当。

项目连接：管理类数据写入时，标签、服务、审核记录要保证事务边界清晰。

### 自定义 Starter 怎么实现？

答题要点：定义配置属性、自动配置类、条件装配、暴露 Bean、提供注解或客户端工具。

项目连接：log-starter 提供统一注解和 AOP 切面，各业务系统引入依赖即可记录操作日志。

## MySQL / Redis

### 慢 SQL 怎么排查？

答题模板：

> 我会先通过慢日志或监控定位具体 SQL，再用 explain 看索引命中、扫描行数、join 顺序和 Extra。如果是索引问题，判断是否能加联合索引或改写条件；如果是数据量问题，考虑分页优化、预计算、分区或冷热分离；如果是架构问题，考虑把分析查询迁到 Doris。

### 缓存和数据库如何保证一致？

答题要点：先更新数据库，再删除缓存；读时未命中再回源；对短暂不一致可接受的配置类数据设置过期时间；重要数据用消息通知或 Canal 类方案。

## 分布式 / 高可用

### MQ 如何保证不丢消息？

答题要点：生产端确认、Broker 持久化和副本、消费者手动提交 offset、失败重试、死信或补偿。

项目连接：用户行为数据可以容忍短暂延迟，但不能无感丢失；关键任务要有补偿链路。

### 限流、熔断、降级区别是什么？

- 限流：流量太大时保护自己。
- 熔断：依赖持续失败时快速失败，避免拖垮调用方。
- 降级：非核心能力先停掉或返回兜底结果。

项目连接：大模型 API、外部数据源、日志服务都适合做超时、熔断和降级。

## 大数据 / AI

### Kafka 到 Flink 到 Doris 如何保证幂等？

答题要点：Kafka 可能重复投递；Flink 开 Checkpoint；业务数据用唯一键或版本号；Doris 写入设计去重模型或覆盖逻辑；失败后允许重放。

### 大模型打标结果不稳定怎么办？

答题模板：

> 我会从输入、输出、工程兜底三层处理。输入上使用固定 Prompt 模板和候选标签，输出上要求 JSON Schema 或固定结构，解析失败自动重试。工程上做超时、限流、降级和人工审核，低置信度结果不直接生效。

## 反问准备

你可以问面试官：

- 团队当前更关注业务交付、架构治理，还是性能稳定性？
- 数据平台的实时性要求大概是秒级、分钟级还是离线 T+1？
- 线上故障排查主要依赖哪些监控和链路追踪工具？
- AI 能力在业务中是探索阶段还是已经有生产流量？
