# MySQL、Redis、Doris 与 Elasticsearch

> 这是简历命中率最高的一页。优先掌握 MySQL 索引、事务、慢 SQL，以及 Redis 一致性、缓存问题和分布式锁；Doris 与 Elasticsearch 用 BFI 项目串起来。

## MySQL / SQL 高频题

### 1. 为什么 MySQL 索引常用 B+Tree？

**回答：** B+Tree 是多路平衡树，单个节点可以存放大量键，树高低，能减少磁盘 I/O；数据集中在叶子节点，内部节点只保存索引键和指针；叶子节点有序连接，范围查询和排序友好。红黑树分支少，数据量大时树高更高；Hash 索引又不适合范围和排序。

### 2. 聚簇索引和二级索引有什么区别？

**回答：** InnoDB 聚簇索引的叶子节点保存完整行数据，一张表只有一个，通常是主键；二级索引叶子节点保存索引列和主键值。通过二级索引查询非覆盖列时，需要再回到聚簇索引查整行，这就是回表。主键应尽量短、稳定、递增，避免所有二级索引膨胀和频繁页分裂。

### 3. 什么是联合索引的最左前缀？

**回答：** 联合索引按定义顺序排序，查询从最左列开始并连续使用时最容易定位范围。例如索引 `(a,b,c)` 可以支持 `a`、`a,b`、`a,b,c`；跳过 `a` 时通常不能利用这棵树完成直接定位。是否真正使用仍要看优化器、选择性和查询成本，以执行计划为准。

### 4. 常见索引失效场景有哪些？

**回答：** 常见问题包括对索引列做函数或计算、隐式类型转换、`LIKE '%xxx'` 前置通配、联合索引跳过左列、选择性太低导致优化器放弃索引，以及不符合排序规则。不能只背“范围后失效”，MySQL 版本和 Index Condition Pushdown 会影响实际行为，最终要看 `EXPLAIN`。

### 5. 覆盖索引是什么？

**回答：** 查询需要的列都能从某个索引中取得，不需要回表，就是覆盖索引。它能减少随机 I/O，适合高频读接口；但不能为了覆盖所有查询不断加宽索引，因为索引会增加存储、写放大和维护成本。

### 6. `EXPLAIN` 重点看什么？

**回答：** 先看访问类型 `type`，再看候选索引和实际 `key`、预计扫描 `rows`、过滤比例以及 `Extra`。需要关注全表扫描、回表量、临时表、文件排序、Join 顺序和分区裁剪。执行计划是估算，必要时结合真实执行信息、慢日志和数据分布判断。

### 7. 你如何排查一条慢 SQL？

**回答：**

> 我先通过慢日志或链路监控定位 SQL、参数、频率和耗时分布，再用 EXPLAIN 看扫描量、索引、Join 和 Extra。随后判断是索引缺失、SQL 写法、深分页、返回过多、锁等待，还是数据量已经不适合事务库。优化后用接近生产的数据和参数回归，比较耗时、扫描行数和资源消耗，而不是只确认“用了索引”。

**项目落点：** BFI 的多维筛选不能只靠给 MySQL 加索引；TB 级分析应进入 Doris，通过分区、分桶和预计算解决。

### 8. 深分页为什么慢？怎么优化？

**回答：** `LIMIT offset,size` 仍需要扫描或排序前面的 offset 行，再丢弃它们，offset 越大越慢。可以使用基于唯一有序键的游标分页，例如 `id > lastId`；必须跳页时可先用覆盖索引查主键，再回表关联。分页必须有稳定排序，防止漏数和重复。

### 9. ACID 分别是什么？

**回答：** 原子性保证事务内操作要么全部成功要么全部失败；一致性表示事务前后业务约束成立；隔离性控制并发事务互相可见程度；持久性保证提交结果在故障后仍能恢复。InnoDB 通过 undo log 支持回滚和 MVCC，通过 redo log 支持持久性，锁和 MVCC 共同实现隔离。

### 10. MySQL 的隔离级别和并发问题有哪些？

**回答：** 读未提交可能脏读；读已提交避免脏读，但同一事务两次读取可能不同；可重复读保证快照读取一致，InnoDB 还通过 MVCC 和 next-key lock 处理很多幻读场景；串行化隔离最强但并发最低。选择隔离级别要根据一致性要求和并发成本。

### 11. MVCC 是什么？

**回答：** MVCC 通过行记录隐藏字段、undo log 版本链和 Read View，让普通快照读在不阻塞写的情况下读取合适版本。读已提交通常每次语句生成新 Read View，可重复读通常事务首次快照读后复用，因此可见性不同。当前读仍会读取最新版本并按需要加锁。

### 12. redo log、undo log、binlog 分别做什么？

**回答：** redo log 是 InnoDB 的物理日志，用于崩溃恢复和持久性；undo log 保存旧版本，用于事务回滚和 MVCC；binlog 是 Server 层逻辑日志，用于复制和数据恢复。提交时要协调 redo 与 binlog，避免主库恢复状态和复制日志不一致。

### 13. 什么情况下会发生死锁？怎么处理？

**回答：** 多个事务以不同顺序持有并等待对方需要的锁，会形成循环等待。数据库可以检测后回滚其中一个事务；应用要捕获死锁错误并对幂等事务有限重试。预防方式包括统一访问顺序、缩短事务、精确索引、减少锁范围，避免事务中执行外部远程调用。

## Redis 高频题

### 14. Redis 为什么快？

**回答：** 数据主要在内存，核心数据结构高效；命令执行路径避免了复杂磁盘随机 I/O；事件循环减少线程切换和锁竞争。Redis 6 之后可以用多线程处理网络 I/O，但命令执行的核心模型仍强调串行语义。快不代表可以存无限数据，大 key、慢命令和持久化仍会造成抖动。

### 15. Redis 常用数据结构和项目场景是什么？

**回答：** String 适合缓存、计数和分布式锁；Hash 适合对象字段；List 可做简单队列但可靠消息更适合专业 MQ；Set 适合去重和交并集；ZSet 适合排行榜和按分值排序。还可以用 Bitmap 做状态统计、HyperLogLog 做近似去重、Stream 做消息流。

### 16. 缓存穿透、击穿、雪崩有什么区别？

**回答：** 穿透是查询不存在的数据，每次都打到数据库，可用参数校验、空值缓存或布隆过滤器；击穿是单个热点 key 失效瞬间大量回源，可用互斥重建、逻辑过期和热点预热；雪崩是大量 key 同时失效或 Redis 故障，可用过期时间打散、多级缓存、限流降级和高可用。

### 17. 缓存和数据库如何保持一致？

**回答：** 常用 Cache Aside：读时先查缓存，未命中回源并写缓存；写时先更新数据库，成功后删除缓存。它只能实现最终一致，删除失败要通过重试、消息或订阅数据库变更补偿；缓存设置合理 TTL。强一致业务不能把缓存当事实源，应直接读数据库或使用更严格方案。

### 18. 为什么通常是删除缓存而不是更新缓存？

**回答：** 更新缓存可能需要重新计算复杂数据，并且并发写时旧值可能后到覆盖新值；删除让下一次读取从数据库加载最新值，逻辑更简单。代价是删除后的短暂回源和最终一致窗口，需要通过补偿机制降低风险。

### 19. Redis 分布式锁如何实现？

**回答：** 单实例基础实现使用 `SET key value NX PX ttl` 原子加锁，value 使用唯一请求标识；释放时用 Lua 脚本先比较 value 再删除，防止误删别人的锁。任务可能超过 TTL 时需要受控续期。分布式锁不能替代数据库唯一约束，关键正确性还要考虑 Redis 故障和主从切换。

### 20. RDB 和 AOF 有什么区别？

**回答：** RDB 是某个时刻的数据快照，文件紧凑、恢复快，但两次快照之间可能丢数据；AOF 记录写命令，数据更完整，但文件更大，需要重写，恢复通常更慢。生产中可以组合使用，具体取舍看恢复点目标、恢复时间目标和资源开销。

### 21. 主从、哨兵和 Cluster 分别解决什么问题？

**回答：** 主从用于数据复制和读扩展，但不会自动完成可靠故障转移；哨兵监控主从并在主节点故障时选主，解决高可用；Cluster 将 key 分到多个槽和节点，解决容量与水平扩展，同时提供故障转移。跨槽多 key 操作、热点 key 和扩容迁移是 Cluster 的设计重点。

### 22. 什么是大 key 和热 key？

**回答：** 大 key 是单个 key 的 value 或成员过大，会阻塞删除、传输、持久化和迁移；热 key 是访问集中在少量 key，可能打满单节点网络或 CPU。治理包括拆分、压缩、限制成员、异步删除、本地缓存、读副本和热点隔离，同时通过监控先确认真实分布。

## Doris / Elasticsearch / Oracle 高频题

### 23. 为什么 BFI 的分析查询使用 Doris 而不是 MySQL？

**回答：** MySQL 擅长事务和点查，TB 级多维聚合、大范围扫描会影响事务负载。Doris 是面向分析的列式存储和分布式执行系统，能通过分区裁剪、并行扫描、向量化执行、预聚合和物化视图提升聚合查询效率。业务主数据仍由事务库管理，不能让 Doris 替代所有数据库。

### 24. Doris 分区和分桶怎么设计？

**回答：** 分区通常按时间等可裁剪维度管理数据生命周期，查询带时间条件时减少扫描；分桶决定分区内数据分布，常选择分布较均匀且参与高频关联或过滤的字段。桶数太少并行度不足，太多会产生小 tablet 和元数据开销，需要结合数据量、节点数和并发测试。

### 25. 明细模型、聚合模型和主键模型怎么选？

**回答：** 明细模型保留原始记录，适合行为明细和灵活分析；聚合模型在导入和查询阶段按 key 聚合，适合固定指标；主键模型按 key 保留最新版本，适合更新和去重。选择取决于是否保留明细、更新方式和查询口径，不是模型越“高级”越好。

### 26. Doris 查询突然变慢怎么排查？

**回答：** 先看是否命中分区裁剪、扫描数据量、过滤和聚合是否下推、Join 分布、数据倾斜、物化视图命中、并发和节点负载。再检查导入小文件、分桶不均、统计信息和版本变化。优化要通过 Query Profile 和真实指标验证。

### 27. Elasticsearch 的倒排索引是什么？

**回答：** 倒排索引从“词项到包含该词项的文档列表”建立映射，适合全文检索；关系库普通索引更像从行键定位记录。写入时文本经过 analyzer 分词形成词项，查询时也要使用兼容的分析方式。

### 28. `text` 和 `keyword` 有什么区别？

**回答：** `text` 通常会分词，用于全文检索；`keyword` 不分词，适合精确过滤、聚合和排序。一个字段可以通过 multi-fields 同时提供两种形式。mapping 一旦设计错误，很多字段类型不能直接原地修改，通常需要新索引和 reindex。

### 29. Elasticsearch 深分页怎么处理？

**回答：** `from + size` 很大时，每个分片都要保留大量候选并由协调节点合并，成本很高。连续翻页使用 `search_after` 加稳定排序，导出或一致性遍历可结合 PIT；旧方案 scroll 更偏批量处理。产品层也应限制任意跳转到非常深的页。

### 30. Oracle 和 MySQL 在项目中需要注意哪些差异？

**回答：** 常见差异包括分页语法、序列或自增方式、日期函数、空字符串语义、执行计划和锁行为。迁移或多数据库支持时应隔离方言，不在业务代码中到处拼兼容 SQL；对关键 SQL 分数据库做集成测试。

## 15 分钟速记

- MySQL：B+Tree、联合索引、回表、EXPLAIN、MVCC、三种日志。
- 慢 SQL：先证据，后定位；看参数、频率、扫描量，不只看是否命中索引。
- Redis：穿透是不存在，击穿是单热点，雪崩是大面积；Cache Aside 是最终一致。
- Doris 管大范围分析，Elasticsearch 管检索，MySQL 管事务，Redis 管热点访问。
