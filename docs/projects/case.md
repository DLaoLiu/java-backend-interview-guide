# 最新简历项目表达手册

> 主讲项目只保留三个：Chat-BFI、BFI 和通用日志平台。ServiceTag 用作大模型 API 追问补充，NFI 和油气田项目用于证明业务交付经验。

## 项目通用表达结构

按六句话组织，不要上来罗列技术栈：

1. **背景：** 谁遇到了什么问题。
2. **目标：** 系统要提供什么能力。
3. **职责：** 你负责哪些明确边界。
4. **难点：** 数据量、稳定性、一致性或业务复杂度。
5. **方案：** 为什么选择这些技术，关键流程是什么。
6. **结果与复盘：** 只说真实数据；没有数字就说能力和改进方向。

## Chat-BFI（第一主项目）

### 1 分钟版本

> Chat-BFI 是公司内部开发的 BFI 对话式分析 Agent，目标是让业务人员通过自然语言完成多步骤数据查询。项目由一名前端和一名后端组成，我负责后端开发；后来因部门调整和整条业务线取消而没有上线。
>
> 我使用 LangChain 封装模型和 Tool，用 LangGraph 固定编排相关性判断、输入规范化、Schema 召回、结构化任务规划、人工确认和逐步 SQL 执行。每一步生成一条 SQL，失败最多重试三次；步骤之间通过带过期管理的 Doris 逻辑 View 引用结果，State 和 Checkpoint 持久化到 PostgreSQL。
>
> 当前完成了 SQL 语法和趋势/明细特征校验，但完整 AST、权限、超时和执行计划检查仍属于后续演进，不能说成已实现。

### 5 分钟必须展开

- 输入：问题、历史消息和当前 Checkpoint State。
- 检索：相关表字段召回，使用 `BAAI/bge-reranker-v2-m3` 重排。
- 计划：模型输出固定 JSON，服务端校验后由用户确认或补充信息重规划。
- 执行：每步生成一条 SQL，做语法及趋势/明细特征校验，异常最多重试三次。
- 衔接：Doris 逻辑 View 保存查询定义，业务表登记过期时间，定时任务清理。
- 边界：当前不是 ReAct；完整 SQL 安全防线和上下文压缩尚未完成。

## BFI 用户行为分析平台（第二主项目）

### 1 分钟版本

> BFI 已在成都和黑龙江落地，团队 6 人。平台每天处理约 20 亿条、每条 8 个字段的原始记录，数据保留半年，为业务提供用户画像、筛选、碰撞和布控分析。
>
> 还原机解析报文后写入 Kafka，Flink 清洗并按业务分发到 Doris；画像任务再由 Flink 从 Doris 读取和计算，写入 Elasticsearch。我主要负责后端，也开发部分 Flink 任务。全量数据按周拆表、表内按天分区，布控数据按月拆表，并结合 IMSI 等字段的分桶与索引支撑查询。

### 5 分钟必须展开

- 数据源和业务实体是什么。
- 为什么 Kafka、Flink、Doris、ES 各自不可互相替代。
- 用户画像、碰撞分析如何转成查询或计算。
- Checkpoint 为什么不等于端到端不重。
- 周表、月表、日分区、分桶和索引分别解决什么问题。
- Flink OOM 如何从热点 Key 和全量窗口定位。

### 最可能追问

- TB 级数据量如何确认？日增量和保留周期是多少？
- Kafka 消息如何保证不丢和不重？
- Flink Exactly-once 是否覆盖到 Doris？
- Doris 为什么比 MySQL 合适？
- 做过哪一条真实的性能优化？

真实项目答案：[BFI 项目问答](/projects/bfi-interview)；原理参考：[Flink、Doris 与 AI 工程](/bigdata-ai)、[分布式与性能](/distributed-performance)

## 通用日志监控平台（第三主项目）

### 1 分钟版本

> 多个业务系统都需要统一操作审计，复制日志代码会造成维护和口径不一致，所以我们把能力封装为 log-starter。业务方法使用自定义注解标记，AOP 切面采集用户、方法、参数摘要、耗时、结果和异常，再通过 Feign 或异步通道发送到日志服务。
>
> 我负责 Starter 架构、切面和日志发送客户端。设计上通过配置属性和条件装配降低接入成本，使用隔离线程池、超时和降级避免日志服务故障影响主业务；敏感参数需要脱敏，审计日志和普通日志使用不同可靠性策略。

### 5 分钟必须展开

- 自定义注解定义哪些元数据。
- AOP 使用 JDK 还是 CGLIB 代理，自调用有什么问题。
- 自动配置如何根据类路径和配置创建 Bean。
- 用户、requestId 等上下文如何获取和跨线程传递。
- 异步队列满、远程调用失败、日志服务不可用时怎么办。

### 最可能追问

- Starter 最少需要哪些组件？
- 为什么不用业务代码手动记录日志？
- 切面异常会不会影响主业务？
- 日志异步后丢失怎么办？
- 如何避免记录密码、身份证等敏感数据？

详细答案：[Spring、MyBatis 与微服务](/framework)

## ServiceTag（加分项目）

### 1 分钟版本

> ServiceTag 统一管理 App、小程序和 Web 服务的标签体系。我负责核心后端和大模型 API 集成，将服务信息和候选标签组成结构化 Prompt，要求模型按固定 Schema 返回建议；服务端执行候选范围和业务规则校验，低置信度或冲突结果进入人工审核。接口侧通过超时、限流、有限重试、缓存和降级保证稳定，人工修改用于后续评测和规则优化。

### 只准备这些追问

- 结构化输出失败怎么办？
- 如何评估标签准确率？
- 人工审核如何反哺？
- 如何控制 Token 和成本？
- 为什么不让模型结果直接入库？

## 项目真实性检查

面试前为每个项目写清以下信息，无法确认的不要说具体数字：

- 实际团队人数、你的职责边界。
- 数据来源、日增量、保留周期。
- 真实使用的组件和版本。
- 你亲自解决的一次问题。
- 优化前后的可验证指标。
- 哪些是已经上线，哪些只是后续设计。
